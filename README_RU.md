# Separate Bobbers: Persistent Hooks 1.1.0 (исходный проект)

Это исходный проект-доработка предоставленного `separatebobbers-1.0.0.jar` для Minecraft Java 1.21.11 / Fabric.

## Что добавлено

- Таблица связей `игрок + ID удочки -> UUID поплавка` сохраняется в `data/separatebobbers_persistent_bobbers.dat` в данных мира через `PersistentState`.
- При повторном использовании удочки мод пытается загрузить сохранённую сущность поплавка из её измерения и чанка.
- Сущности, которые принадлежат сохранённым записям, не тикают, если владелец вышел, находится в другом измерении или выбрал другую удочку. Это должно предотвращать удаление поплавка ванильной проверкой владельца и оставлять его на нажимной плите.
- При восстановлении поплавок привязывается к текущему экземпляру игрока, а не к старому объекту из предыдущей сессии.
- Очистка при выходе теперь очищает только ссылки в оперативной памяти, а не сохранённые записи.

## Важные ограничения

**Этот проект не был собран и протестирован в самой игре в текущей среде.** Код - best-effort прототип, который нужно собрать и проверить на копии мира. Особенно важно протестировать:

1. Заброс поплавка на нажимную плиту и переход в Незер.
2. Выход из игры и повторный вход.
3. Полную остановку и перезапуск сервера.
4. ПКМ той же удочкой: должна удалиться именно связанная с ней сущность, а запись должна исчезнуть.
5. Несколько удочек и несколько поплавков.
6. Что чанк с механизмом загружен и тикает: сохранённый поплавок не заставит незагруженный чанк выполнять редстоун.

Сначала сделай резервную копию мира. Если сборка падает, сохрани полный вывод ошибки Gradle и исправляй её до теста на основном мире.

## Сборка

Требуется Java 21 и Gradle, способный запускать Fabric Loom 1.18.3. Нужен доступ в интернет для загрузки Minecraft/Fabric-зависимостей при первом билде.

Из папки проекта:

```bash
gradle build
```

В Windows можно открыть папку как Gradle-проект в IntelliJ IDEA, либо выполнить эту команду в терминале, где `gradle` доступен в PATH.

Готовый JAR после успешной сборки находится в `build/libs/`.

## Установка для теста

1. Скопируй сохранение мира в безопасное место.
2. Используй Minecraft Java 1.21.11, Fabric Loader и Fabric API.
3. Удали старую версию `separatebobbers-1.0.0.jar` из `mods`, чтобы не загрузить две версии одного `mod id`.
4. Положи новый JAR из `build/libs/` в `mods`.
5. Проведи тесты на копии мира.

## Техническое замечание

Мод сохраняет индекс UUID поплавков и рассчитывает на то, что сама сущность `FishingBobberEntity` штатно сохраняется в данных чанка. Это требует проверки в реальном серверном запуске. Если ванильная версия не сохраняет такую сущность в нужном состоянии, следующим шагом понадобится отдельная стратегия восстановления сущности; одних сохранённых координат недостаточно.

## Автоматическая сборка через GitHub Actions

В проект добавлен workflow `.github/workflows/build.yml`. После загрузки проекта в GitHub:

1. Создай новый репозиторий на GitHub.
2. Загрузи туда **содержимое** папки `separatebobbers-persistent` (включая скрытую папку `.github`).
3. Открой вкладку **Actions**. При первом использовании GitHub может попросить разрешить запуск workflows.
4. Открой запуск **Build mod** и дождись завершения задания.
5. Внизу страницы запуска в разделе **Artifacts** скачай `separatebobbers-persistent-jars.zip`. Внутри будут собранные JAR-файлы.

Если сборка завершится ошибкой, открой шаг **Build mod**, скопируй полный текст ошибки и проверь его перед дальнейшей публикацией. Успешная сборка подтверждает компиляцию, но не заменяет проверку мода в Minecraft.
